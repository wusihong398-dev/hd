# 硬盘健康卫士 v0.4.0 实施规格与验收标准

## 目标
将 v0.3.2 的“读取数据/启动检测命令”升级为可在软件内闭环展示的硬盘诊断流程。所有诊断结论、证据、限制和建议必须直接显示在中文界面，并可导出报告；不得要求用户复制日志交给外部人员分析。

## 产品原则
1. 不将 SMART 不支持、驱动/控制器不透传、权限不足或读取超时误报为硬盘损坏。
2. 区分健康状态、自检结果、表面只读扫描结果和文件系统检查结果，不得互相替代。
3. 不同厂商 SMART 原始值采取设备型号/协议/属性定义匹配；未知属性保留原始值并标为“厂商定义未知”，不得套用通用单位。
4. 所有检测均明确说明是否只读、是否由硬盘固件执行、是否会写入用户数据。
5. 兼容现有 SQLite 历史档案；升级数据库必须使用向前迁移并保留旧数据。
6. 不自动执行修复、写零、格式化、擦除、重映射或任何破坏性操作。

## 1. 设备识别与介质分类
- 使用 Windows 存储 API / CIM 与 smartctl JSON 结果联合识别物理设备。
- 分类字段：SSD、HDD、NVMe SSD、未知/虚拟/RAID/USB 桥接设备。
- 优先根据 BusType、MediaType、NVMe 协议标识、RotationRate、ATA/NVMe 设备类型判定；证据冲突时显示“类型待确认”，不根据型号字符串猜测。
- 每块设备显示型号、序列号（默认脱敏）、容量、接口、总线、介质类型、盘符映射、PhysicalDrive 编号、SMART 通道与可用性。

## 2. SMART 厂商属性解释
- 保留 smartctl 原始 JSON 和原始属性行。
- 属性解释采用可测试的规则注册表：厂商/型号/协议/属性 ID/属性名称匹配。
- 至少覆盖常见 ATA 属性：05 重映射扇区、09 通电小时、0C 通电次数、BB 报告不可校正错误、BC 命令超时、C5 待映射扇区、C6 离线不可校正扇区、C7 CRC 错误；厂商定义不同的属性不得强行赋予统一含义。
- NVMe 显示 Critical Warning、Available Spare、Available Spare Threshold、Percentage Used、Data Units Read/Written、Power On Hours、Unsafe Shutdowns、Media Errors、Error Log Entries。
- Samsung / Western Digital / Seagate / Kingston 等厂商使用型号与 smartmontools drive database 辅助识别，但最终仍以协议和已验证属性规则为准。
- 解释失败时显示“原始属性（未解释）”，而不是 Unknown_Attribute 作为无上下文结论。

## 3. SSD 寿命
- UI 统一显示“厂商报告的已用寿命”和“估算剩余寿命”两个字段。
- NVMe Percentage Used：已用寿命百分比；剩余寿命仅按 max(0, 100 - percentage_used) 显示，并注明这是厂商报告的耐久度估算，不是剩余使用年限保证。
- ATA SSD 仅在识别到型号/厂商已验证的寿命属性时计算；无可靠字段则显示“设备未提供/无法可靠计算”。
- 禁止将任意 SMART ID 169/202/寿命相关名称未经型号验证直接解释成百分比。

## 4. 健康指标与风险诊断
- 展示重映射扇区、待映射扇区、不可校正扇区、接口 CRC 错误、NVMe Media Errors、温度、通电时间、SSD 耐久度。
- 健康评分范围 0–100，同时显示风险等级：良好、关注、警告、严重、数据不足。
- 评分必须来自可解释规则，逐项显示扣分/加分原因和证据；不能用 SMART overall PASSED 单独判定绝对健康。
- CRC 错误非零但未增长时标记“历史累计/观察”；与上次有效快照相比增长时标记“新增接口传输错误，检查数据线/接口/供电”，不能直接判定介质坏道。
- SMART 数据不足时不伪造分数，显示“数据不足”，并说明缺失的检测证据。
- 报告分别陈述“已观察到的事实”“风险推断”“建议操作”。

## 5. 全盘只读表面扫描可视化
- 以扫描块为基础保存区块状态和扫描覆盖率；状态至少包含未扫描、正常、慢速、读取错误、复核确认错误。
- 颜色：绿色=读取正常；黄色=读取明显慢于本盘动态基线/设定阈值；红色=读取失败或复核失败；灰色=未扫描。
- 不得将单次速度低直接称为坏道；必须注明慢速阈值、块大小、设备缓存/后台负载可能影响速度。
- 展示磁盘区块分布图、错误位置列表、扫描速度统计、P50/P95、错误数量、扫描耗时、完成/中止状态。
- 慢速区块必须以相同范围进行受控复测，避免只凭一次抖动上色。
- 保留只读属性；扫描期间不写测试数据，不自动修复。

## 6. SMART 自检状态机
- 自检记录字段：设备身份、PhysicalDrive、测试类型、启动时间、设备预计完成时间、轮询时间、进度、终态、原始输出、Self-test Log 证据、退出/中断原因。
- 状态：准备中、已提交/等待设备、进行中、完成通过、完成失败、被主机中止、设备中止、无法读取结果、设备不支持、状态未知。
- 启动命令成功只显示“已提交”，不能显示“通过”。
- 启动后自动轮询 smartctl -c / -a JSON 与 SMART Self-test Log；轮询间隔动态退避，短测默认约 10–15 秒，长测默认约 30–60 秒。
- 进度与剩余时间以设备报告为准；设备不报告进度时显示“设备未提供进度”，不能自行假定。
- 读取 Self-test Log 确认终态，记录失败 LBA/失败阶段（如果设备提供）。
- 同一设备同一时刻只允许一个自检；运行期间禁用短测/长测按钮并提示当前测试，不重复提交。
- 软件退出时提示正在运行的设备自检由硬盘固件继续执行；重启软件后可恢复查询并关联未完成记录。
- SMART 自检不可用时显示具体 smartctl messages、退出位、设备类型与可能的控制器透传原因。

## 7. 每盘历史与自动报告
- 每块硬盘独立显示 SMART 快照、自检历史、表面扫描历史和趋势。
- 记录设备身份匹配质量；序列号不可用时使用型号+容量+PNP/设备路径组合，并标记身份可靠度。
- 报告包括硬盘信息、介质类型、SMART 属性、关键指标、健康评分及规则依据、自检状态/历史、扫描热区图、读取异常区间、限制说明、建议。
- 支持中文 HTML 和 JSON 导出；导出报告应明确数据时间戳和软件版本。
- 日志只作为诊断证据，不要求用户手工解读。

## 8. UI 页面
- 首页/总览：全部物理硬盘卡片、介质类型、健康等级、温度、寿命、未完成自检状态。
- 单盘诊断：健康评分、关键风险指标、证据与建议。
- SMART 属性：解释值、原始值、属性来源/可信度。
- 自检中心：当前进度、预计完成时间、最近结果、历史列表。
- 坏道扫描：进度、速度曲线、区块热力图、异常区间。
- 健康历史：按硬盘身份筛选和趋势对比。
- 报告中心：一键生成所选硬盘报告/全部硬盘报告。

## 9. 自动化验收矩阵
### 单元测试
- ATA 属性解析、NVMe 属性解析、厂商规则优先级、未知属性回退。
- SSD/HDD/NVMe/未知设备分类与冲突输入。
- 寿命计算边界（0、1、100、>100、缺失、非法值）。
- 评分规则、证据链、数据不足场景。
- 自检状态机：启动成功不等于通过；进行中/完成/失败/中断/设备不支持/日志不可读。
- 同设备重复自检防护与跨设备并发策略。
- SQLite 迁移、旧历史档案兼容、进程异常后恢复未完成自检。
- 扫描块颜色分类、慢速复核逻辑、停止/暂停后的覆盖率。

### 集成测试
- mock smartctl JSON 与文本输出，不依赖真实硬盘。
- 模拟 SMART 短测/长测轮询并验证最终 Self-test Log。
- 模拟 SMART 不支持、USB/RAID 透传失败、权限不足、设备拔出。
- 模拟 CRC 历史累计与新增增长的差异。
- 报告内容与数据库记录一致。

### Windows 真机验收
- SATA SSD、SATA HDD、NVMe SSD 至少各一块。
- USB 外接盘/桥接设备和无法读取 SMART 的设备作为兼容性用例。
- 对每块设备完成 SMART 快照、短自检（设备支持时）、扩展自检（设备支持时）、只读扫描。
- 真机测试不执行写入式坏道测试，不以虚拟模拟结果冒充硬盘实测。
- 生成 EXE 后在无 Python、无 CMD 窗口环境启动，检查 UAC、中文界面、数据库持久化和报告导出。

## 10. 发布门槛
- 不得仅以源码提交或 CI 编译成功宣称版本完成。
- 必须有单元/集成测试报告、Windows EXE 构建产物、SHA256、第三方许可证说明、真机验收状态。
- 未实测项目必须标记“未实测/受硬件限制”，不得宣称通过。
