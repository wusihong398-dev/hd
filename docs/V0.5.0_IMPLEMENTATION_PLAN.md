# 硬盘健康卫士 v0.5.0 开发计划

## 版本目标
在 v0.4.1 的 Windows x64 单文件程序基础上，开发健康总览、可解释风险诊断、寿命数据展示、历史趋势和中文报告中心。保留已有设备列表、SMART、SMART 自检自动轮询、只读扫描和彩色扫描网格。

## 产品要求
- 所有检测结论在程序内直接展示，不要求用户复制日志到外部分析。
- 事实、风险推断、建议分开显示；未知和不支持必须明确显示，不伪造健康结论。
- 评分必须可解释；关键 SMART 证据不足时显示“数据不足”，不得用温度或 SMART PASSED 单独给出高分。
- 不写入测试数据，不执行修复、写零、格式化、擦除或重映射。
- 历史数据保留，数据库升级使用可回滚/可恢复的迁移策略。

## 1. 健康总览
- 总览卡片显示每块物理硬盘：型号、容量、盘符、介质类型、温度、SMART 可用性、健康等级、评分（仅在证据充分时）。
- 支持全部硬盘和单盘筛选。
- 显示当前运行中的 SMART 自检与扫描状态。
- 对 SMART 不支持/读取失败显示原因类别，不把设备直接判坏。

## 2. 智能诊断与健康评分
- 复用现有诊断规则注册表；评分必须逐条展示证据、原始值、解释值、扣分原因。
- 分级：良好、关注、警告、严重、数据不足。
- 05 重映射、C5 待映射、C6 不可校正、NVMe Media Errors、Critical Warning、Available Spare 等按协议/型号可信度解释。
- C7 CRC 非零但未增长标记为历史累计观察；相比上次快照增长才提示新增接口传输错误。
- 报告区分介质风险与接口/连接风险。
- 不将读取失败直接定性为坏道；记录 Win32 错误、复测结果和 LBA/偏移（设备提供时）。

## 3. SSD 寿命
- 展示厂商提供的 Percentage Used / Wear Level / Life Left 等可靠属性及数据来源。
- NVMe 剩余耐久度显示 max(0, 100 - Percentage Used)，并标明“厂商耐久度估算，不是剩余年限”。
- ATA SSD 仅使用已验证型号规则；否则显示“设备未提供/无法可靠计算”。
- HDD 不显示虚假的 SSD 剩余寿命。

## 4. 历史趋势
- 每盘保存 SMART 快照、自检记录、扫描报告摘要。
- 图表支持温度、通电小时、CRC、重映射、待映射、不可校正、NVMe Media Errors、SSD Percentage Used。
- 比较最近两次快照的变化，明确数值增量和时间。
- 历史中设备身份不确定时，不合并不同物理设备记录。

## 5. 中文诊断报告
- 一键生成单盘 HTML 报告和 JSON 数据；PDF 若依赖缺失可后续增加，不阻塞 HTML/JSON。
- 报告包含设备信息、采集时间、SMART 原始/解释值、评分依据、风险事实、扫描分布、异常位置、自检历史、限制说明和建议。
- 扫描未完成时明确覆盖率和未扫描区域；黄色慢速区块不得称为确认坏道。
- 报告生成失败要在 UI 显示具体原因。

## 6. 界面
- 新增“健康总览”“历史趋势”“报告中心”页面/标签。
- 现有 SMART、自检中心、坏道扫描、智能诊断功能保留。
- 支持中文显示、窗口缩放、长内容滚动、表格列宽调整。
- 每个结论提供“为什么这样判断”展开说明。

## 7. 测试
- 单元测试：评分证据充分性、CRC 增量/不增量、NVMe 寿命边界、缺失属性、设备身份匹配、趋势差值、报告生成。
- 集成测试：模拟多硬盘 JSON、SMART 不支持、USB/SCSI 透传失败、未完成扫描、正在运行的自检。
- 数据库迁移测试：旧历史档案保留、升级失败回滚。
- GUI 冒烟：标签可切换、报告导出、历史加载、长文本滚动。
- 真机验收：用户实际 Windows 电脑上的 SATA/NVMe/USB/SCSI 设备；未实测功能必须标记待验收。

## 8. 发布门槛
- 先审计现有 v0.4.1 源码结构和数据库接口，再接入新页面；禁止猜测方法名后盲目字符串替换。
- 自动化测试通过后才构建 EXE。
- 交付 EXE、SHA256、第三方许可证、测试报告和已知限制。
- CI 成功只表示构建成功，不代表真实硬盘测试通过。
